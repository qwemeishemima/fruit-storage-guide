# 鲜存记

鲜存记是一款面向家庭用户的蔬果保存工具，帮助用户快速查询“能不能放冰箱、怎么放、能放多久”，并记录家里的食材保鲜期。

一句话定位：

> 查怎么存，记别放坏。

产品说明：

> 鲜存记是一款面向家庭用户的蔬果保存工具，帮助用户快速查询食材保存方式，记录食材保鲜期，减少放坏浪费。

## 当前阶段

项目已完成本地 MVP，当前进入“本地 MVP 收尾阶段”。

当前阶段继续坚持：

- 使用微信小程序原生 WXML / WXSS / JavaScript。
- 使用本地静态食材数据。
- 使用微信小程序本地 storage 保存“我的食材”。
- 不接入云开发、登录、订阅消息、AI、后台管理、支付、会员等远期能力。

## 核心功能

当前本地 MVP 已支持：

- 首页搜索入口。
- 首页分类入口。
- 首页快捷专题入口，可按标签进入筛选结果。
- 首页“大家常查”食材。
- 首页“今日小贴士”。
- 按关键词搜索食材，支持名称、别名、关键词和标签匹配。
- 按分类浏览食材。
- 标签筛选结果页。
- 查看食材详情，包括冷藏建议、保存方式、保存时间、密封建议、怕水/干燥建议、乙烯影响、买回后建议、保存小贴士等。
- 食材不存在状态。
- 从详情页把食材加入“我的食材”。
- 添加“我的食材”时支持“今天买的 / 昨天买的 / 前几天买的”快捷选择。
- “我的食材”使用本地 storage 保存记录，storage key 为 `myFoods`。
- 在“我的食材”中查看、删除已添加食材。
- 在“我的”页清空全部“我的食材”记录。
- 根据 `addedAt` 和食材 `shelfLife` 计算预计食用状态。
- “我的食材”按状态排序，快过期和可能不新鲜的食材排在前面。
- “我的食材”概览，包括总数和建议尽快吃数量。
- “我的”页本地数据概览，包括我的食材数、尽快吃数量和已收录食材数量。

当前阶段不包含：

- 云开发。
- 登录、注册或用户体系。
- 云端同步或多设备同步。
- 订阅消息或真实提醒。
- AI 保存建议。
- 后台管理系统。
- 支付或会员。

## 本地运行方式

1. 打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本仓库根目录。
4. AppID 使用 `project.config.json` 中配置的 AppID，或选择测试号。
5. 不启用云开发。
6. 点击“编译”运行小程序。

运行后可验证：

- 首页搜索框进入搜索页并自动聚焦。
- 首页快捷专题入口进入对应标签筛选结果。
- 首页分类入口进入分类页。
- 分类页切换分类并查看真实食材列表。
- 搜索 `番茄` 可找到 `西红柿`，搜索 `青瓜` 可找到 `黄瓜`，搜索 `马铃薯` 可找到 `土豆`。
- 点击食材卡片进入详情页。
- 访问不存在的食材 id 时，详情页展示空状态。
- 在详情页点击底部按钮，将食材加入“我的食材”。
- 添加时选择“今天买的 / 昨天买的 / 前几天买的”。
- 在“我的食材”页查看预计食用状态、概览和排序结果，并删除记录。
- 在“我的”页查看本地数据概览，并可清空“我的食材”。

## 数据说明

食材数据集中维护在 `data/foods.js`，当前约 142 条。

分类数据集中维护在 `data/categories.js`，当前约 8 类。

页面不应重复硬编码完整食材数据。需要读取食材时，优先使用 `utils/food.js` 中的工具函数：

- `getAllFoods()`
- `getFoodById(id)`
- `getFoodsByCategory(categoryId)`
- `searchFoods(keyword)`
- `getFoodsByTag(tag)`
- `getCategoryById(categoryId)`

食材数据主要字段包括：

- `id`
- `name`
- `aliases`
- `keywords`
- `category`
- `image`
- `summary`
- `fridgeAdvice`
- `storageMethod`
- `roomTempShelfLife`
- `coldShelfLife`
- `shelfLife`
- `sealedAdvice`
- `waterAdvice`
- `ethyleneAdvice`
- `tips`
- `afterPurchaseAdvice`
- `tags`

“我的食材”相关本地存储逻辑集中在 `utils/pantry.js`，storage key 为：

```text
myFoods
```

记录结构：

```js
{
  recordId,
  foodId,
  name,
  addedAt
}
```

`utils/pantry.js` 会根据记录中的 `addedAt` 和食材数据中的 `shelfLife` 计算本地预计食用状态。完整食材信息仍从静态数据中读取，避免本地 storage 中的数据和食材库更新后不一致。

## 后续计划

本地 MVP 收尾阶段优先考虑：

- 我的食材按状态分组展示。

- 搜索别名和标签体验优化。

暂不考虑：

- 云开发。
- 登录、注册、用户体系。
- 订阅消息或真实提醒。
- AI 保存建议。
- 后台管理系统。
- 支付或会员。
- 云端同步或多设备同步。

## 开发原则

- 一次只做一个模块。
- 优先使用最简单、最稳、最适合本地 MVP 收尾阶段的方案。
- 不提前引入云开发、登录、消息通知、AI 等复杂能力。
- 不在页面中重复维护食材数据。
- 不做大规模重构。
- UI 保持清爽、自然、生活化，适合家庭日常工具。
